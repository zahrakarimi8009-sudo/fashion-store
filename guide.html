۱. این پروژه چیست؟

یک فروشگاه اینترنتی زعفرانی/زنانه، کاملاً فارسی و راست‌چین، بدون هیچ فریمورکی (نه Vue، نه React، نه Laravel). پروژه از سه لایه ساخته شده:

  • فرانت‌اند: صفحات HTML + CSS تمیز + جاوااسکریپت خالص
  • بک‌اند: فایل‌های PHP در پوشه‌ی api/ (یک REST API کوچک با خروجی JSON)
  • داده: دیتابیس MySQL با نام nila_shop (فایل آماده: nila_shop.sql)
نکته‌ی مهم طراحی: اگر PHP/دیتابیس در دسترس نباشد (مثلاً کسی فایل‌ها را مستقیم در مرورگر باز کند)، صفحات با داده‌های نمایشی کار می‌کنند و هیچ خطایی نمی‌دهند. یعنی کد هم برای یادگیری و هم برای اجرا واقعیت‌گرایانه است.

۲. معماری: همه‌چیز چطور با هم کار می‌کند؟

وقتی مثلاً در پنل مدیریت محصولی می‌سازی، این زنجیره اتفاق می‌افتد:

کاربر روی «ثبت و افزودن محصول» می‌زند
js/admin.js فرم را می‌خواند → درخواست (JSON یا FormData برای آپلود عکس)
→ api/admin.php (سرور) درخواست را اعتبارسنجی می‌کند
→ در دیتابیس products ثبت می‌کند (و فایل تصویر را در images/ می‌نویسد)
→ جواب JSON برمی‌گردد → پنل تازه می‌شود و صفحه‌ی اصلی فروشگاه هم همان محصول جدید را می‌بیند (چون از api/products.php می‌خواند)

دو «سشن» جداگانه

  • مشتری: صفحه‌ی login.php بعد از ورود موفق، $_SESSION['nila_user'] را می‌سازد. همه‌ی APIهای مشتری (سفارش، پیام، اعلان، پروفایل) فقط با این سشن کار می‌کنند.
  • مدیر: اکشن login در api/admin.php سشن $_SESSION['nila_admin'] را می‌سازد. ۲۱ اکشن مدیریت (داشبورد، سفارش، کاربر، محصول، پیام، تنظیمات...) فقط با این سشن مجازند.

رمز عبور

داده‌های نمونه با روش نمایشی sha256 + نمک ثابت ذخیره شده‌اند (برای سادگی در دیتابیس اولیه)؛ حساب‌های جدید با password_hash() امن ساخته می‌شوند. تابع verify_password() در config/db.php هر دو را تشخیص و راستی‌آزمایی می‌کند.

۴. نصب گام‌به‌گام (روی WAMP / XAMPP)

  1. WAMP (یا XAMPP) را نصب و روشن کن (آیکون سبز در سینی سیستم).
  2. پوشه‌ی fashion-store را داخل D:\wamp64\www کپی کن (پسوند PHP باید فعال باشد — در WAMP پیش‌فرض فعال است).
  3. به http://localhost/phpmyadmin برو → برگه‌ی Import → فایل nila_shop.sql (داخل پوشه‌ی پروژه) را انتخاب کن → Execute.
  4. اگر نام کاربری/رمز MySQL تو با پیش‌فرض فرق دارد، فایل config/db.php را باز کن و مقادیر DB_USER / DB_PASS / DB_NAME را اصلاح کن. (پیش‌فرض: root با رمز خالی و دیتابیس nila_shop — همانی که در WAMP/XAMPP پیش‌فرض است.)
  5. صفحه را باز کن: http://localhost/fashion-store
  6. سلامت‌سنجی: http://localhost/fashion-store/diag.php — اگر هر ۷ چراغ سبز بود، همه‌ی بخش‌ها روی دیتابیس واقعی کار می‌کنند.
✅ اگر diag.php همه سبز است: چیزی دیگر لازم نیست. پنل مدیریت (admin.php) و پنل کاربری واقعاً به دیتابیس وصل‌اند.

انتقال به هاستینگ (cPanel و مشابه)

  • فایل‌ها را در public_html (یا ساب‌دومین) آپلود کن.
  • در cPanel → MySQL Databases دیتابیس بساز، کاربر بده و nila_shop.sql را از phpMyAdmin هاست ایمپورت کن.
  • فقط config/db.php را با نام کاربری/رمز/دیتابیس هاست ویرایش کن.
  • مطمئن شو PHP هاست نسخه‌ی ۷.۴ یا بالاتر دارد (پیشنهاد: ۸.x).

۶. پنل مدیریت — چه کارهایی واقعاً روی دیتابیس انجام می‌شود؟

بخشعملیات واقعی
داشبوردتعداد سفارش‌ها/کاربران/محصول‌ها/درآمد (جمعی سفارش‌های غیرلغو‌شده) + ۴ سفارش اخیر — همه از MySQL
سفارش‌هالیست کامل، تغییر وضعیت (ثبت شده/در انتظار پرداخت/در حال ارسال/تحویل شده/لغو) و حذف — در پنل مشتری هم لحظه‌ای دیده می‌شود
کاربرانلیست + افزودن (با کنترل تکراری بودن شماره) + حذف
مدیران و دسترسیلیست + سطح دسترسی (مدیر کل/مدیر فروشگاه/پشتیبانی/مشتری) + افزودن/حذف (حذف آخرین مدیر کل مسدود است)
پیام‌هاگفت‌وگوهای همه‌ی مشتریان + علامت خوانده‌شده + پاسخ (پاسخ تو در پنل همان مشتری ظاهر می‌شود)
محصولاتلیست + افزودن (با پیش‌نمایش زنده‌ی کارت + آپلود تصویر) + ویرایش (فرم خودکار پر می‌شود) + حذف + فعال/غیرفعال (غیرفعال‌ها از فروشگاه پنهان می‌شوند). هر تغییر لحظه‌ای در صفحه‌ی اصلی و صفحه‌ی محصول اعمال می‌شود چون فروشگاه از دیتابیس می‌خواند.
تنظیمات سایتنام فروشگاه، تماس، ایمیل، آدرس، هزینه ارسال، سقف ارسال رایگان، کد تخفیف — ذخیره در جدول settings

نوار وضعیت بالای پنل (نشانگر کوچک سبز/نارنجی) به تو می‌گوید آیا این لحظه دیتابیس وصل است یا نه. اگر دیتابیس نباشد، یک نوار قرمز بزرگ هم با دلیل دقیق خطا بالا می‌آید.

۷. پنل کاربری (account.html)

  • پروفایل من: اطلاعات واقعی از دیتابیس + ویرایش (با کنترل تکراری بودن شماره)
  • سفارش‌های من: سفارش‌های واقعی با وضعیت، اقلام و جمع‌بندی + اعلان «ثبت سفارش»
  • پیام‌ها: گفت‌وگو با پشتیبانی (پاسخ ادمین همان‌جا ظاهر می‌شود)
  • اعلان‌ها: اعلان‌های واقعی + «همه را خوانده‌شده علامت بزن»
  • تغییر رمز عبور: با راستی‌آزمایی رمز فعلی — ذخیره در دیتابیس
  • تنظیمات: ترجیحات حساب (ذخیره در مرورگر)

۸. آپلود تصویر محصول

  • در فرم «افزودن/ویرایش محصول» دو فیلد دارد: تصویر محصول و تصویر دوم (هنگام هاور روی کارت).
  • فرمت: JPEG / PNG / WEBP — حداکثر ۳ مگابایت. تصویر انتخاب‌شده زنده روی کارت پیش‌نمایش دیده می‌شود.
  • فایل با نام up-...jpg در پوشه‌ی images/ ذخیره و مسرش در دیتابیس نوشته می‌شود؛ پس بعد از رفرش و حتی تغییر سرور (با کپی images) جا دارد.
  • اگر فایلی انتخاب نکنی، تصویر پیش‌فرض همان دسته به‌کار می‌رود.
  • هنگام ویرایش اگر تصویر جدید بگذاری، قبلی (اگر آپلودشده باشد) پاک می‌شود. هنگام حذف محصول هم تصویر آپلودشده‌اش حذف می‌شود — تصاویر نمونه‌ی اصلی (p1.jpg و...) هرگز دست نمی‌خورند.

۹. منطق «خریدار تأییدشده»

وقتی یک مشتری واردشده نظری ثبت می‌کند، API بررسی می‌کند آیا در یکی از سفارش‌های این کاربر، آن محصول وجود داشته یا نه:

reviews.user_id = کاربرِ لاگین‌شده + orders.user_id = همان کاربر + order_items.product_id = همان محصول
→ اگر هر سه جور شدند: is_verified = 1 → برچسب «خریدار تأییدشده» روی نظر
  • برچسب دینامیک است: هر خریداری که آن محصول را خریده باشد، هر وقت نظر بدهد برچسب می‌گیرد.
  • نظری که بدون ورود ثبت شود (یا محصولی که کاربر نخریده) برچسب نمی‌گیرد.
  • دیتابیس نمونه‌ای که تحویل داده می‌شود ۱۰ نظر آماده روی هر ۸ محصول دارد (چندتای تأییدشده) تا ظاهر بخش نظرات کامل باشد.
